# KTV Studio 字幕工作台設計

- 日期：2026-08-28
- 狀態：已與使用者確認，進入實作
- 目標：讓使用者不依賴 Whisper，也能直接修改歌詞、匯入歌詞並手動對準歌曲時間。

## 1. 問題與產品決策

目前字幕來源雖然已加入 YouTube 與 LRCLIB，但找不到歌詞時仍可能使用 Whisper；唱歌辨識的文字可能不準。既有「貼歌詞重新辨識」會改善提示，但仍需要等待 AI，且不能保證每句文字完全正確。

因此新增一個本機字幕工作台，將「文字正確性」與「時間軸正確性」交給使用者控制：

- 文字可直接逐句修改，不重新下載、分離人聲或執行 Whisper。
- 可匯入純文字、LRC、SRT、VTT。
- 已有時間碼的格式直接載入；純文字歌詞轉成待對齊的逐行字幕。
- 播放伴奏時，以「標記開始」與「標記結束並下一句」逐句打點。
- 儲存後立即更新 KTV 顯示與之後錄製的影片字幕。
- 保留既有 LRCLIB 與貼歌詞重新辨識功能，兩者可作為編輯器的起始資料。

## 2. 使用流程

1. 使用者進入錄唱室，開啟「字幕工作台」。沒有字幕時工作台自動展開。
2. 選擇一種方式取得內容：
   - 編輯目前字幕；
   - 選擇 `.txt`、`.lrc`、`.srt`、`.vtt` 檔案；
   - 將歌詞貼入匯入文字區。
3. 純文字歌詞會顯示「尚未對齊」狀態；使用者按播放，游標停在要處理的句子。
4. 按「標記這句開始」記錄目前播放秒數；按「標記結束並下一句」記錄結束，並自動把下一句設為目前句、方便連續打點。
5. 任一字幕列也可以直接修改文字、開始秒數、結束秒數；可以跳到該句播放。
6. 使用者可新增、刪除、拆分、合併字幕列。拆分預設使用文字輸入框游標位置，未選取時使用文字中點，時間則按比例切分。
7. 按「儲存字幕」後，前端送完整逐句資料到本機 API。成功回傳正規化後的字幕，父頁立即更新 KTVLyrics 與 VideoPanel。

未儲存的修改保留在當前頁面並顯示提示；重新整理頁面前由使用者決定是否儲存。第一版不加入音訊波形拖曳時間軸，避免複製剪輯軟體的複雜度；秒數欄位與播放打點已能完成精準對齊。

## 3. 高階架構

```text
┌────────────────────────────────────────────────┐
│ StudioPage                                     │
│  shared audioRef + current Subtitles           │
│  KTVLyrics / VideoPanel                         │
│  SubtitleEditor                                │
│   ├─ local parser: TXT / LRC / SRT / VTT       │
│   ├─ playback marker: audio.currentTime        │
│   └─ draft lines + save                        │
└──────────────────────┬─────────────────────────┘
                       │ PUT /api/songs/{id}/subtitles
┌──────────────────────▼─────────────────────────┐
│ FastAPI                                         │
│  validate request and line limits               │
│  build_subtitles_json(language/title/manual)    │
│  atomic replace song/subtitles.json              │
└──────────────────────┬─────────────────────────┘
                       │
                local subtitles.json
```

解析在瀏覽器執行，因為匯入檔案本身不需要上傳到後端；後端只接受已整理的字幕列並負責最後驗證、中文正體化、日文羅馬拼音與持久化。這符合全本機原則，也避免新增暫存上傳檔案的生命週期。

## 4. 資料與 API

`subtitles.json` 的 `source` 擴充為 `manual`。儲存的每列格式仍然是既有合約：

```json
{
  "start": 12.34,
  "end": 16.02,
  "text": "手動修正後的歌詞",
  "words": null
}
```

手動修改文字或時間後，無法安全保證既有逐字 `words` 仍與內容、時間一致，因此編輯器送出的列不帶 `words`，後端以 `words: null` 組裝。KTV 會退回逐句高亮，文字與時間正確優先於錯誤的逐字高亮。

新增 `PUT /api/songs/{song_id}/subtitles`：

```json
{
  "lines": [
    {"start": 0, "end": 4.2, "text": "第一句"},
    {"start": 4.2, "end": 8.8, "text": "第二句"}
  ]
}
```

後端限制：最多 2,000 列、每列文字最多 500 字元、時間為有限非負數、`end >= start`；空白文字列拒絕。歌曲與 metadata 不存在回 404，資料格式錯誤回 500，寫檔失敗回 500。寫檔使用同資料夾暫存檔後 `replace`，避免瀏覽器讀到半份 JSON。

## 5. 前端互動與可及性

- 工作台是可收合的 `SubtitleEditor`，標題顯示目前來源及未儲存狀態。
- 每列有文字 `textarea`、開始/結束秒數欄位、跳轉、標記、拆分、合併、刪除操作。
- 目前對齊列以靛紫邊框突出，儲存/匯入/標記期間有明確 disabled 狀態。
- 檔案匯入使用隱藏 file input 搭配可聚焦按鈕；所有控制有繁體中文 `aria-label`。
- 時間顯示同時提供 `mm:ss.xx` 預覽與可輸入秒數，避免只能靠滑鼠。
- 純文字匯入若尚未打點，顯示「待對齊」而不是假裝已經有時間。
- 匯入會取代目前草稿；若有未儲存修改，先以瀏覽器確認提示。
- 解析失敗、格式不支援、超過行數/字數、儲存失敗都在工作台內顯示可理解的錯誤，不阻塞播放。

## 6. 重要決策（ADR 摘要）

### ADR-001：前端解析匯入檔

選擇瀏覽器解析 TXT/LRC/SRT/VTT，而不是把檔案先上傳後解析。匯入內容可能包含受版權保護的歌詞，留在本機瀏覽器更符合產品的 local-first 約束，也不需要新的檔案清理工作。代價是解析器要用 TypeScript 覆蓋四種常見格式。

### ADR-002：用逐句打點取代第一版波形編輯器

選擇共享播放器時間、兩個標記按鈕與秒數欄位。這能精準完成使用者需求，實作與維護成本遠低於波形縮放、拖曳碰撞與虛擬化時間軸。未來仍可在同一份 `start/end` 資料上加入波形視圖。

### ADR-003：手動字幕清除 words

當文字或時間被改動時保留舊 words 會造成高亮與歌詞錯位。手動來源改用逐句顯示，並由 backend 重新產生日文羅馬拼音/中文正體字，優先保證文字與整句時間軸正確。

## 7. 驗收條件

- 沒有字幕的歌曲可直接開啟工作台、貼上純文字、逐句打點並儲存。
- 編輯現有字幕文字後，儲存、重新整理仍保留修正內容。
- LRC/SRT/VTT 的時間軸正確載入；純文字不會被錯誤賦予虛假時間。
- 打點下一句會自動銜接上一句 `end` 與下一句 `start`。
- 儲存後 KTVLyrics、VideoPanel 使用新文字與時間；日文仍有羅馬拼音。
- 不影響既有 YouTube、LRCLIB、Whisper、貼歌詞重新辨識流程。
- API 驗證、解析器測試、前端 TypeScript build 均通過。
